## المطلوب بالضبط — نفّذ الحاجات دي حرفياً

1. **استعرض الريبو**

   * clone أو فتح الريبو محليًا. اعمل فحص سريع للـ framework (Vite / CRA / Next / Expo).
   * شغّل `git grep` أو `rg` للبحث عن أي URLs **hardcoded**:

     ```bash
     git grep -n "http://" || true
     git grep -n "https://" || true
     git grep -n "al-mugwumpian-patience" || true
     ```
   * سجّل كل الملفات اللي فيها روابط ثابتة أو قيم env مش مستخدمة.

2. **تأكد أن كل طلبات API تستخدم متغيرات البيئة**

   * ابحث عن ملف إعدادات http client (axios/fetch wrapper) وتأكد إن `baseURL` أو أي URL مبني من:

     * `process.env.EXPO_PUBLIC_API_URL` أو `process.env.EXPO_PUBLIC_API_BASE_URL`
     * أو `process.env.VITE_*` / `process.env.REACT_APP_*` / `process.env.NEXT_PUBLIC_*` حسب الـ framework.
   * إذا لقيت hardcoded URLs، وثّقها وقدم diff مقترح.

   **مقتـرح نموذج axios (تعديله لو لازم):**

   ```js
   import axios from 'axios';

   const base = process.env.EXPO_PUBLIC_API_BASE_URL
     || process.env.VITE_API_BASE
     || process.env.REACT_APP_API_BASE
     || process.env.NEXT_PUBLIC_API_BASE
     || process.env.EXPO_PUBLIC_API_URL;

   const api = axios.create({ baseURL: base, timeout: 15000 });
   export default api;
   ```

3. **تحقق من ملفات البناء وبيئات Netlify وEAS**

   * **Netlify:** اذكر للمستخدم الخطوات اللي لازم يعملها أو إن انت مسهّلها:

     * تأكد من وجود المتغيرات في Netlify UI أو باستخدام Netlify CLI:

       ```bash
       netlify env:set EXPO_PUBLIC_API_URL "https://al-mugwumpian-patience.ngrok-free.dev" --site <SITE_ID>
       netlify env:set EXPO_PUBLIC_API_BASE_URL "https://al-mugwumpian-patience.ngrok-free.dev" --site <SITE_ID>
       ```
     * تأكد أن build command يقرأ المتغيرات (مثلاً VITE يحتاج إعادة build بعد تغيير env).
   * **EAS / Expo:**

     * اطلب من المستخدم أنك ستحقق من أن الكود يقرأ `EXPO_PUBLIC_*` من `process.env` أو `Constants.expoConfig.extra`.
     * للتجهيز لEAS builds، استخدم:

       ```bash
       eas secret:create --name EXPO_PUBLIC_API_URL --value "https://al-mugwumpian-patience.ngrok-free.dev"
       eas secret:create --name EXPO_PUBLIC_API_BASE_URL --value "https://al-mugwumpian-patience.ngrok-free.dev"
       ```
     * أو ضع المتغيرات في `eas.json` build profile كـ env vars إذا المشروع معد كده.

4. **افحص CORS وطرق المصادقة**

   * شوف باك-اند: هل يسمح origins لنتلايف و ngrok domain؟
   * اقتراحات (قدّم patch إن طالبته):

     * Flask: `CORS(app, origins=["https://<netlify-site>.netlify.app","https://al-mugwumpian-patience.ngrok-free.dev"])`
     * Express: `app.use(cors({ origin: ['https://...','https://al-mugwumpian-patience.ngrok-free.dev'], credentials: true }))`
   * تأكد أن أي auth headers (Authorization / cookies) يتم إرسالها عبر نفس الإعدادات.

5. **اختبارات برمجية وتقنية (قابلة للتشغيل عند المستخدم)**

   * اعمِل لائحة أوامر على شكل copy-paste يقدر المستخدم يشغّلها محليًا بعد ما يشغّل ngrok عنده:

     ```bash
     # health check
     curl -I https://al-mugwumpian-patience.ngrok-free.dev/api/health

     # full endpoint test
     curl -sS https://al-mugwumpian-patience.ngrok-free.dev/api/some-endpoint | jq
     ```
   * Browser console fetch test:

     ```js
     fetch('https://al-mugwumpian-patience.ngrok-free.dev/api/some-endpoint')
       .then(r=>r.json()).then(console.log).catch(console.error);
     ```

6. **سيسجل الوكيل أي مشاكل ويوفر حلول دقيقة**

   * لو لقى hardcoded URL: قل له يقدّم snippet لتعديل + مكان السطر + PR branch `fix/ngrok-env`.
   * لو لقى نقص في env usage: يضيف ملف `.env.example` أو يحدّث README بخطوات الضبط (Netlify + EAS).
   * لو لقى مشاكل CORS أو خطأ 401/403: يسجل cause + suggested code fix.

7. **تجميع تقرير تسليم نهائي (ملف واحد في الريبو)**

   * `ngrok-integration-check-report.md` يحوي:

     * قائمة المتغيرات اللي اتأكدت وصحتها (أسماء + قيم اللي استعملتها).
     * الملفات اللي اتفحّصت والتغييرات المقترحة (path + diff).
     * أوامر اختبار جاهزة للمستخدم (curl, fetch).
     * لائحة أخطاء إن وجدت + حلول خطوة بخطوة.
     * (اختياري) branch/PR مع التعديلات لو انت نفّذت تغييرات config (سجّل كل commit).

8. **قواعد صارمة للوكيل — اقرأها كويس**

   * **ممنوع** تشغيل ngrok أو إنشاء أي tunnel أو نشر على Replit. لا تغيّر إعدادات السيرفر أو البورتات.
   * **ممنوع** تعديل واجهات UI أو إعادة تصميم. التغييرات يجب أن تكون config / env / code glue فقط.
   * أي تغيير تنظره ضروري يعمل PR منفصل مع شرح: "why" + "how to roll back".
